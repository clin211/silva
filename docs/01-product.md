# Developer Hub 产品文档

- 版本：1.2
- 状态：第一阶段产品与验收基线
- 产品形态：个人 Developer Hub + Headless CMS + 自动化数据采集
- 架构原则：前后端分离、API-first、模块化单体、静态优先

## 1. 产品定位

Developer Hub 是面向开发者与技术受众的个人技术门户。它提供个人档案、技术文章与 AI 开源趋势，并配有独立的 CMS 管理后台。

- **内容发布**：Markdown 文章、分类标签、草稿、不可变修订、审核、发布和取消发布。
- **个人档案**记录个人介绍、经历、技能与公开社交链接。
- **自动化数据采集**从 GitHub 获取 AI 仓库数据，保存历史快照并更新公开榜单。

## 2. 第一期范围与边界

| 领域        | 一期必做                                                                       | 后续或不做                                                                      |
| ----------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| CMS         | 草稿、修订历史、预览、审核、手动发布与取消发布、分类标签、封面与 SEO           | 定时发布、版本对比、整站回滚、已发布文章的 slug 改名均后续                      |
| 个人档案    | 维护个人资料，保存后进入公共站点发布流程                                      | 个人档案草稿、修订与审核后续                                                     |
| AI Trending | GitHub 自动采集、历史快照、7/30 天增长、筛选、趋势详情、任务状态和有限人工修正 | 其他数据源、24h 榜单后续；不手工录入榜单                                        |
| 管理与运维  | 内置角色分配、账户停用、媒体管理、采集和发布任务、基础审计与健康检查           | 自定义角色和权限编辑、访客账户、收藏和站内搜索后续                              |

### 2.1 AI Trending 自动采集

- 一期由 GitHub 公开仓库的配置 topic 白名单发现候选，排除 fork、已归档及非公开仓库，以 GitHub 仓库 ID 去重；页面明确这是收录范围内的榜单，不宣称覆盖全 GitHub。
- 每天按 UTC 时间窗口采集。保存仓库身份、描述、topics、语言、License 和上游时间，以及 Stars、Forks、Open Issues、最近可获取的 release 与快照时间。后台记录批次状态、限流和错误。
- 默认展示近 7 天 Stars 净增长，可切换近 30 天或其他排序。增长由历史快照相减；可为负数，数据不足显示「数据不足」而不是 0。展示榜单数据日期。若本轮失败或仅部分成功，不发布该批次；保留最近一次完整榜单，尚无成功批次时展示「暂无数据」。具体计算口径见 [后端 §7.1](03-backend-technical.md#71-ai-采集流程与排名口径)。
- 人工操作限于隐藏/恢复、精选及分类修正，不直接修改采集指标。精选单独展示，不改变自然排名。管理员可以重试当日未成功的批次，不生成重复快照。

## 3. 用户与权限

| 角色    | 一期权限                                                                                                |
| ------- | ------------------------------------------------------------------------------------------------------- |
| Visitor | 无需登录即可只读访问已上线的公开站点                                                                    |
| Author  | 创建文章、读取和编辑自己的文章及修订、上传和引用自己的已校验媒体、提交审核；不能审核、发布或取消发布    |
| Editor  | 管理所有文章和媒体、审核指定修订、发布/取消发布、维护分类标签和个人资料、调整 AI 榜单展示、查看相关任务 |
| Admin   | 包含 Editor 权限，并管理账户、分配内置角色、触发采集、重试发布以及查看审计和系统状态                    |

采用 RBAC 和资源归属检查。即使一期只有一名管理员也保留 users、roles、permissions 及关联表；允许 Editor/Admin 审核自己编写的修订，但必须完成明确的审核动作，不能隐式跳过审批。后台支持创建/停用账户、分配内置角色；不提供公开注册。

## 5. CMS 功能范围

- **文章**：Markdown 编辑、安全预览、自动保存、修订历史、分类标签、封面与 SEO；独立显示编辑版本、待上线目标与当前线上版本。已上线的旧版可以在新版编辑或审核期间保持可见。
- **个人资料**可维护简介、经历、技能和社交链接。
- **AI Trending**支持隐藏或恢复榜单仓库、标记精选及修正分类。
- **系统**：账户与角色、媒体上传和管理、发布任务状态和失败原因、采集任务与限流状态、审计日志和系统健康。

## 6. 内容与发布工作流

1. 保存文章（包括自动保存）创建不可变 revision；文章正文、分类标签选择、封面及 SEO 随该 revision 冻结。旧草稿与当前线上内容互不影响。文章 slug 在首次被接受发布后锁定，一期不改名。
2. 提交审核锁定具体 revision。批准或拒绝只作用于该 revision；后续编辑产生新 revision，不继承旧版的批准。拒绝新版不撤下当前线上版本。
3. **发布**是接受一个已批准的 revision 作为期望公开版本，并排队构建。**取消发布**是将期望公开版本清空，再排队构建。公开分类标签、个人资料、AI 榜单人工调整和成功采集批次也进入同一发布流程。分类或标签更名作为独立的站点更新排队。
4. **上线**是成功激活一个站点版本（`generation`）。Canonical 静态站点和 Public API 都读取同一当前线上版本；旧构建不能覆盖新版本。构建失败保留上一线上版本，后台显示失败并允许 Admin 重试当前待上线版本。
5. 取消发布在包含该变更的站点版本上线后生效：公开 API 和详情路由返回 404，列表、sitemap 与 RSS 移除该文章。正常构建和队列条件下，人工发布或取消发布的待上线目标为 5 分钟内；构建失败或超时应在后台可见。上线前旧版仍可访问；不保证召回已经下载的副本或第三方缓存。一期不提供紧急下线或整站回滚；需要恢复文章内容时，可重新发布历史上已批准的 revision，仍生成新的站点版本。

## 7. 非功能要求

- **SEO、性能**：静态 HTML、canonical、Open Graph、结构化数据、sitemap 和 RSS；只有筛选、图表等需要交互的区域按需请求 API。
- **安全**：后台浏览器通过同源 `/api` 访问；使用 HttpOnly Secure Cookie、CSRF 与 Origin 校验、资源级 RBAC、限流；Markdown 渲染消毒，上传校验前保持私有。
- **维护与可观测性**：Rust 模块化单体、Worker 独立进程；结构化日志、request ID、任务状态、错误记录及审计日志。
- **备份**：备份 PostgreSQL，并保护当前线上版本所依赖的媒体和产物；上线前演练一次恢复。

## 8. 第一阶段交付顺序

1. 基础设施、登录、RBAC、媒体上传与确认。
2. 文章、修订、分类标签、审核、发布和取消发布，打通构建及线上切换。
3. Astro 前台基础栏目与 SEO。
4. 个人资料管理与 About 页面展示。
5. GitHub AI 项目采集、历史快照和趋势页。
6. 完成审计、恢复演练与端到端验收。

## 9. 验收标准

- **修订隔离**：v1 上线后保存 v2 并修改分类标签、封面及 SEO，再送审或拒绝，访客仍只看到 v1，且任何旧 revision 都没有被覆盖。未获批准的 revision 不能发布。
- **发布一致性**：先完成新构建、后完成旧构建，线上仍为新版本；构建失败不替换线上产物；成功取消发布后，详情和 API 返回 404，列表、sitemap、RSS 不再包含该文章。
- **权限及上传**：Author 不能修改他人文章或执行发布；未确认或未通过校验的上传不能被引用或公开访问。
- **个人资料**的修改随站点版本上线，About 和公开 API 读取同一版本。
- **AI Trending**：每日采集重试不重复入库；一批只成功一部分时保留上次完整榜单；增长计算含负增长与数据不足两种用例。
- **访问边界**：浏览器和 Astro 构建器都不直连 PostgreSQL；前者走服务端 API，构建器只读取指定站点版本的构建快照。
