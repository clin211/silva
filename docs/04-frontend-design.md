# Developer Hub 前端页面设计

- 范围：一期公开站点（Website）与管理后台（Admin）。
- 用途：定义页面、路由、区块顺序、响应式布局和交互状态，作为原型与实现的依据。
- 配套草图：[前端页面线框图册（PDF）](04-frontend-wireframes.pdf)。每条路由独立编号，首页与 About 另画手机布局。
- 相关文档：[产品范围](01-product.md)、[前端技术方案](02-frontend-technical.md)、[后端接口与数据模型](03-backend-technical.md)。后台路径以管理域为基准，与公开站点分开。

## 1. 设计方向与全站布局

公开站点像一个持续更新的个人技术主页，而不是产品营销页：先说明是谁、写什么、做什么，再引导访客阅读文章或探索资源。后台以内容编辑与任务处理为主，优先保证状态可读、操作可预期。

| 项目     | 公开站点                                                                                                 | 管理后台                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 框架     | 顶部导航 → 主内容 → 页脚；站名链接回首页                                                                 | 左侧分组导航＋顶部面包屑与账户菜单＋工作区；登录页独立                                                                                       |
| 导航     | 文章、项目、工具、AI 趋势、MCP 目录、关于；当前栏目高亮，RSS 放页脚                                      | 内容（文章、分类与标签、媒体）、资源（项目、工具、个人资料、MCP）、运行（AI 趋势、站点发布）、系统（账户与角色、审计、系统健康）；按权限显示 |
| 视觉     | 暖白底、深墨正文、墨蓝强调色；用留白和细分隔线拉开层次；少量精选内容才用大卡片                           | 中性底色、紧凑的表格和表单；状态用「文字＋颜色」表达，错误和危险操作明确标注                                                                 |
| 内容宽度 | 桌面外框最大约 1200px，12 栏；文章等长文正文最大约 720px。手机左右各留 16px                              | 桌面侧栏约 224px，工作区随窗口伸缩；表单内容不强行铺满                                                                                       |
| 响应式   | 从 1024px 起启用双栏；768–1023px 优先使用双列卡片，长文和个人档案纵向排列；低于 768px 使用单列与折叠菜单 | 低于 1024px 导航收为抽屉；手机保留必需字段及操作，表格的宽内容仅在表格容器内横向滚动                                                         |

页脚放站点短介、主要栏目、RSS 和已公开的联络链接，不为一期尚未提供的功能放空入口。外链用文字或图标标识，不能仅靠颜色区分。移动端内容顺序与键盘焦点顺序一致；每页一个 `h1`，目录、筛选、编辑器切换和弹窗均可用键盘操作。

## 2. 公开页面清单

| 路由                  | 页面            | 内容布局（从上到下）                                                                                                                                         |
| --------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/`                   | 首页            | 个人首屏 → 文章精选与最近更新 → 精选项目 → AI Trending 摘要 → 关于与联络。详见 §3。                                                                          |
| `/blog`               | 文章列表        | 页标题与栏目说明 → 文章列表（分类、发布日、标题、摘要和可选封面）＋分类/标签侧栏。手机将分类/标签收成列表前的折叠区。                                        |

| `/projects`           | 项目展览        | 页标题与说明 → 精选项目优先展示 → 其他项目卡片网格（名称、简介、状态、技术栈、可选封面）。卡片进入站内详情。                                                 |

| `/ai-trending/[slug]` | AI 项目详情     | 面包屑 → 仓库名称、说明、语言/主题、GitHub 链接 → Stars/Forks 等摘要指标 → 历史趋势图及数据表（无足够样本时显示说明）。                                      |
| `/mcp`                | MCP Server 目录 | 页标题与目录说明 → 分类、Transport、语言筛选 → 卡片网格与分页。卡片含名称、简介、声明的传输方式、语言及核验状态。                                            |
| `/mcp/[slug]`         | MCP 条目详情    | 面包屑 → 名称、摘要与外部链接 → 详情正文、版本列表 → 传输方式、语言、License、来源和核验时间；桌面可将元数据放到右栏，手机按顺序叠放。                       |

## 3. 首页 `/`

参考 [clin.pro 首页](https://clin.pro/) 的展示节奏，而不复制原站文案与装饰：首屏像一本个人刊物的封面；下一屏用一大两小的文章版面，再进入项目与趋势，最后以个人介绍与联络收尾。[查看 W01 桌面与手机草图](04-frontend-wireframes.pdf#page=1)。

### 3.1 首页构图：刊物封面

**先给第一屏足够的尺度。** 桌面导航下，Hero 高度建议随视口在 `480–640px` 间变化（宽屏可从 `65svh` 起调），以 12 栏中的 `8 / 4` 非对称断面分配文字与视觉空间。显示名在桌面约 `72–96px`，一句话定位约 `24–32px`。目标是在常见桌面窗口中仍能看到下方「最近更新」的起始位置，而非让首屏完全挡住内容。

**强对比只留给少数地方。** 暖白和深墨作为底色，右侧用一块抽象的等高线图形压住版面，头像与地点只作小型角标。图形是装饰，不依赖真实头像或额外数据，也不承载信息；字距、基线与图形裁切需对齐后再定稿，不在首屏堆渐变卡片与徽章。

**靠节奏而非卡片数量撑起长页。** 文章用左主右次的大版面，项目与趋势放在一个「正在发生」章节内并列，各自有明确入口；宽屏章节间距建议从 `88–112px` 起调。最后用一条宽幅联络区给页面收尾，不为参考站的「实验台」「正在输入」新增后台字段。

**手机稿要重新排，不是把大页缩小。** `h1` 约 `42–56px`，先让访客看到姓名、定位和「浏览文章」，再出现压低高度的视觉条。图形过挤可弱化，不压按钮和文字。主文章先于两条更新；项目在趋势前，联络最后。精细对齐以手机窄屏与长名字实测为准。

### 3.2 区块与数据

1. **个人首屏**：显示名（`h1`）、定位、简短介绍和「浏览文章」「关于我」两个入口，右侧视觉区仅在资料已配置时叠放头像与所在地角标。未配置个人档案时改用站点名与站点简介，无空名片。
2. **文章精选与最近更新**：左 8 栏放 1 篇已上线精选文章（多篇时取最新），右 4 栏放最多 2 篇不重复的最新文章。没有精选时以最新文章作为主文章并移除「精选」标记；只有一篇时单卡展示。手机先主卡后短列表，标题均链接详情。
3. **精选项目**：最多 3 个已上线精选项目，按现有展示顺序排列。桌面用编号短列表与 AI 趋势摘要并排，手机将两组上下排列。暂无精选时保留「浏览项目」入口，不放空卡片或伪造进展。
4. **AI Trending 摘要**：展示收录范围内近 7 天 Stars 净增长自然榜的前 3 项、榜单数据日期和「查看完整榜单」。复用上线快照与榜单口径，不在首页另算排名；没有成功批次显示「暂无榜单数据」。
5. **关于与联络**：简短介绍链接 `/about`，另给 `/tools` 快捷入口。只展示 Profile 里实际配置的公开社交链接；没有联络资料时不显示空按钮。

## 4. 关于 `/about`

参考 [clin.pro/about](https://clin.pro/about) 的「身份名片 → 个人简介 → 工作经历 → 技术能力 → 联络」结构，弱化简历表格感。内容从已上线 Profile 读取，不引入实时 GitHub 仓库数、语言占比或技能百分比；个人自叙可写在现有的 Markdown 简介里。[查看 W14 桌面与手机草图](04-frontend-wireframes.pdf#page=5)。

```text
顶部导航
┌─ 档案首屏 ──────────────────────────┐
│ 关于我 / 一句话定位       个人名片   │
│ 简介引导                 头像 / 姓名 │
│                          地点 / 社交 │
├─ 个人简介 ── 背景与关注方向 ─────────┤
├─ 经历时间线 ── 日期｜职位、组织、说明 ┤
├─ 技能 ── 按分类组织的技能列表 ────────┤
└─ 保持联系 ── 公开联络 / 阅读文章 ─────┘
页脚
```

| 区块     | 布局与内容                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 档案首屏 | 左 7 栏放「关于我」与个人定位，右 5 栏放身份卡（头像、姓名、地点、已配置的社交链接）。手机先标题再身份卡；缺头像可用姓名首字或省略，不使用默认人物照片。 |
| 个人简介 | 限宽阅读区，渲染 Profile Markdown。背景、关注方向、自叙共用该正文，不强制结构化录入。                                                                    |
| 经历     | 按后台配置顺序展示。桌面日期在左、职位/组织与说明在右；手机把日期放到每段条目顶部。未知日期省略，不把缺少结束时间一律解释为「至今」。                    |
| 技能     | 按分类分组，组内依展示顺序排列；未分类时归为「其他」。熟练程度如有配置则显示原文，不换算百分比。                                                         |
| 联络     | 复用公开社交链接，提供「阅读文章」与「查看项目」。简介、经历、技能为空时省略对应区块；未配置个人档案时保留页标题、简短说明与站内入口。                   |

## 5. 管理后台页面清单

后台列表统一为「页标题与主操作 → 筛选区（如适用） → 表格/卡片 → 分页（如适用）」。详情和表单为「面包屑 → 标题与状态 → 主内容 → 保存或下一步操作」。新建/编辑小表单用抽屉；长表单、需要独立访问的任务详情使用独立页。以下 `{id}` 和 `{revisionId}` 表示后台动态路由段，不是公开 slug。

| 路由或入口                                                    | 页面             | 布局与主要操作                                                                                                                                                |
| ------------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/login`                                                      | 登录             | 居中登录卡：站点标识、账户凭证、提交、错误提示；无公开注册入口。                                                                                              |
| `/`                                                           | 工作台           | 顶部常用操作（如新建文章） → 当前角色有权访问的文章、审核或发布状态摘要 → 相关任务入口；不把全站统计展示给 Author。                                           |
| `/posts`                                                      | 文章列表         | 按权限显示我的文章/全部文章；列表区分编辑/审核状态、期望公开状态和当前线上状态，提供新建及进入编辑页的入口。Editor/Admin 在此筛待审核文章，不单独建审核模块。 |
| `/posts/new`、`/posts/{id}/edit`                              | 文章编辑器       | 顶栏操作及三种版本状态 → Markdown 源码与预览 → 分类、标签、封面、首页精选及 SEO 设置。修订历史、提交审核和发布从编辑页进入；详见 §6。                         |
| `/posts/{id}/revisions`、`/posts/{id}/revisions/{revisionId}` | 历史、预览与审核 | 历史列表显示修订号、时间和审核状态；选中修订打开详情页：修订信息 → 安全预览 → 按权限提交、批准或拒绝该修订。仅在后台访问，无公开预览 URL。                    |
| `/taxonomy`                                                   | 分类与标签       | 分类/标签两个标签页，各为列表＋新增/编辑抽屉；删除前确认，存在引用时显示不能删除的原因。                                                                      |
| `/media`                                                      | 媒体库           | 上传按钮与状态 → 媒体网格 → 详情抽屉。编辑器从媒体选择器插入已就绪媒体；Author 只访问自己的媒体。                                                             |
| `/projects`、`/projects/new`、`/projects/{id}/edit`           | 项目维护         | 列表显示项目状态、精选、排序；表单分基本资料、Markdown 说明、封面、技术栈与链接。项目自身状态和站点上线状态分开显示。                                         |
| `/tools`                                                      | 工具维护         | 分类与排序列表；抽屉维护名称、简介、目标链接、图标与精选设置。                                                                                                |
| `/profile`                                                    | 个人资料         | 单例表单：身份与头像、Markdown 简介、可排序的经历/技能/社交链接；统一保存，独立显示上线状态。                                                                 |
| `/mcp`、`/mcp/new`、`/mcp/{id}/edit`、`/mcp/categories`       | MCP 维护         | 列表展示分类与元数据核验状态；长表单分基本资料、链接、Transport/语言/License、来源及核验，版本在条目内维护，目录分类用独立列表。无启动、运行或代理调用按钮。  |
| `/ai-trending`、`/ai-trending/repositories/{id}`              | AI 项目管理      | 仓库列表显示分类、精选与隐藏状态；详情显示上游指标、快照历史与曲线，人工操作仅限隐藏/恢复、精选和分类修正，不直接编辑采集指标。                               |
| `/ai-trending/runs`                                           | AI 采集批次      | 顶部显示最近一次成功时间；列表显示 UTC 批次、状态、限流和错误，详情用行展开或抽屉；Admin 可请求当日未成功批次，运行中或已成功时显示已有记录。                 |
| `/publishing`、`/publishing/{id}`                             | 站点发布任务     | 列表显示 generation、状态与时间；详情显示构建进度、错误与当前目标/线上版本。仅 Admin 可重试仍为最新目标的失败任务。                                           |
| `/users`、`/roles`                                            | 账户与角色       | 账户表格＋创建/编辑抽屉，支持停用、启用和分配内置角色；角色页为只读列表，不编辑权限定义。                                                                     |
| `/audit-logs`、`/system/health`                               | 审计与系统健康   | 审计用事件表格和详情抽屉；健康页显示检查项与最近结果，不提供未经一期定义的运维操作。                                                                          |
| 403、未匹配路径                                               | 后台异常页       | 显示「无权访问」或「页面不存在」，提供回工作台入口；会话失效转登录，不用 404 掩盖普通的会话失效。                                                             |

账户、角色、审计、系统健康仅对 Admin 开放；目录维护、审核与发布对 Editor/Admin 开放。Author 仅访问自身文章、媒体和服务端允许读取的相关任务。导航与按钮按权限展示，直接访问 URL 仍按服务端授权处理。

## 6. 编辑、发布与状态反馈

- **编辑布局**：宽屏并列「源码｜预览」，文章设置用可收起的右栏；窄屏在「编辑 / 预览 / 设置」间切换，切换不清空表单。页头始终分别标注当前编辑修订、期望公开修订、当前线上修订。未保存内容不作为可审核版本提交。
- **保存与冲突**：明确显示「保存中」「已保存」「保存失败」「有新版本」。并发冲突时停止自动保存、保留当前输入，提示读取最新修订；不静默覆盖。媒体上传另有上传、校验、就绪、失败状态，仅就绪媒体可插入。
- **审核与发布**：审核确认弹窗显示绑定的修订号；发布确认只从已批准的修订中选择，不把当前编辑版本默认当作可发布版本。取消发布单独确认，提示线上内容会在新站点版本激活后下线。两种操作提交后均显示「待上线」，提供任务详情入口；目录和个人资料则保存后直接排队，无文章式修订和审核。
- **任务状态**：`queued` 显示「排队中」，`building` 显示「构建中」，`active` 显示「已上线」，`failed` 显示「构建失败」，`superseded` 显示「已被更新的目标替代」，`retired` 显示「已被新版替换」。待上线超过 5 分钟提示延迟；构建失败仍保留保存成功与原线上状态，不提前显示已上线或已下线。
- **公开筛选与分页**：AI Trending、MCP 只在交互区发起请求，筛选项和页码写入 URL；筛选变更回第一页，浏览器后退可恢复。首屏来自静态快照；符合筛选的记录为零时提示「没有符合条件的结果」并给出「清除筛选」。请求失败显示重试；版本冲突清除旧数据并提示刷新，不混用不同线上版本。
- **数据文案**：AI Trending 默认按近 7 天 Stars 净增长降序，支持 30 天、Forks 增长、Stars 总数与最近更新排序。保留负值，`null` 显示「数据不足」，没有成功批次才显示「暂无榜单数据」。MCP 展示「元数据已核对」等中性文案，不把核验画成安全认证或在线状态。

## 7. 布局验收

1. 分别在 1440px、768px、375px 视口检查首页、About、文章详情、AI 榜单、后台列表与编辑器：内容无整页横向溢出，导航、主操作和状态均可访问。
2. 用无头像、无封面、无精选、无个人资料、长中英文标题和长代码块走查，布局不留空框，正文不因图片或表格撑宽页面。
3. 用键盘完成移动导航、筛选与弹窗操作；焦点可见，关闭弹窗后焦点回到触发控件，状态不只靠颜色表达。
4. 分别走查榜单无批次、筛选无结果、请求失败、站点版本变化；四种反馈可区分。MCP 核验状态不会被误读为安全或可用性承诺。
5. 以 Author 和 Editor/Admin 检查「编辑 → 送审 → 发布」及取消发布的路径：修订标识清楚、越权操作不可用、提交与真正上线状态可区分、保存或上传失败时输入不会丢失。
