# Developer Hub 前端页面设计

- 范围：一期公开站点（Website）与管理后台（Admin）。
- 用途：定义页面、路由、区块顺序、响应式布局和交互状态，作为原型与实现的依据。
- 配套页面见下方[原型索引](#11-原型索引)，首页与 About 均可查看窄屏布局。
- 相关文档：[产品范围](01-product.md)、[前端技术方案](02-frontend-technical.md)、[后端接口与数据模型](03-backend-technical.md)。后台路径以管理域为基准，与公开站点分开。

## 1. 设计方向与全站布局

公开站点是一处持续更新的个人技术主页。先介绍站主和写作方向，再引导访客阅读文章、浏览 AI 开源趋势。后台以内容编辑与任务处理为主，优先保证状态可读、操作可预期。

| 维度     | 公开站点                                                                                                 | 管理后台                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 框架     | 顶部导航 → 主内容 → 页脚；站名链接回首页                                                                 | 左侧分组导航＋顶部面包屑与账户菜单＋工作区；登录页独立                                                                                       |
| 导航     | 文章、AI 趋势、关于。当前栏目高亮，RSS 放页脚 | 内容（文章、分类与标签、媒体）、个人资料、运行（AI 趋势）、系统（账户与角色、审计、系统健康）。各入口按权限显示 |
| 视觉     | 暖白底、深墨正文、墨蓝强调色；用留白和细分隔线拉开层次；少量精选内容才用大卡片                           | 中性底色、紧凑的表格和表单；状态用「文字＋颜色」表达，错误和危险操作明确标注                                                                 |
| 内容宽度 | 桌面外框最大约 1200px，12 栏；文章等长文正文最大约 720px。手机左右各留 16px                              | 桌面侧栏约 224px，工作区随窗口伸缩；表单内容不强行铺满                                                                                       |
| 响应式   | 从 1024px 起启用双栏；768–1023px 优先使用双列卡片，长文和个人档案纵向排列；低于 768px 使用单列与折叠菜单 | 低于 1024px 导航收为抽屉；手机保留必需字段及操作，表格的宽内容仅在表格容器内横向滚动                                                         |

页脚放站点短介、主要栏目、RSS 和已公开的联络链接，不为一期尚未提供的功能放空入口。外链用文字或图标标识，不能仅靠颜色区分。移动端内容顺序与键盘焦点顺序一致；每页一个 `h1`，目录、筛选、编辑器切换和弹窗均可用键盘操作。

| --------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/`                   | 首页            | 个人首屏 → 文章精选与最近更新 → AI Trending 摘要 → 关于与联络。详见 §3。                                                                          |

| `/tags/[slug]`        | 标签文章列表    | 面包屑 → 标签名称与文章数 → 复用文章列表和分类/标签导航。                                                                                                    |
| `/ai-trending`        | AI 趋势榜       | 页标题、GitHub 收录范围与榜单日期（UTC） → 时间窗口、排序、语言、Topic、分类筛选 → 独立精选区 → 自然榜单与分页；手机用紧凑卡片替代表格，保留排名与关键指标。 |
| `/ai-trending/[slug]` | AI 仓库详情     | 面包屑 → 仓库名称、说明、语言/主题、GitHub 链接 → Stars/Forks 等摘要指标 → 历史趋势图及数据表（无足够样本时显示说明）。                                      |

| 未匹配路径            | 404             | 保留站点页头页脚；解释页面不存在或已下线，提供「回首页」「浏览文章」。生产入口返回真实 HTTP 404。                                                            |

RSS、sitemap 和 robots.txt 是站点输出，不列为面向访客的页面。分类与标签入口放在文章列表和详情中，一期不单独增加分类/标签总览页，也不加站内搜索、访客登录、收藏或邮件订阅表单。

## 3. 首页 `/`

首页借鉴 clin.pro 的展示节奏。首屏采用刊物封面式构图，随后呈现文章精选、最近更新和 AI 趋势，最后放个人介绍与联络。[设计参考](https://clin.pro/) · [首页原型](../prototype-design/site/home.html)

### 3.1 首页构图：刊物封面

**先给第一屏足够的尺度。** 桌面导航下，Hero 高度建议随视口在 `480–640px` 间变化（宽屏可从 `65svh` 起调），以 12 栏中的 `8 / 4` 非对称断面分配文字与视觉空间。显示名在桌面约 `72–96px`，一句话定位约 `24–32px`。目标是在常见桌面窗口中仍能看到下方「最近更新」的起始位置，而非让首屏完全挡住内容。

**强对比只留给少数地方。** 暖白和深墨作为底色，右侧用一块抽象的等高线图形压住版面，头像与地点只作小型角标。图形是装饰，不依赖真实头像或额外数据，也不承载信息；字距、基线与图形裁切需对齐后再定稿，不在首屏堆渐变卡片与徽章。

**长页区块。** 文章用左主右次的大版面，随后单独展示 AI 趋势摘要，并链接完整榜单。宽屏章节间距建议从 `88–112px` 起调。最后以宽幅联络区收尾。

**手机布局。** `h1` 约 `42–56px`，先让访客看到姓名、定位和「浏览文章」，再出现压低高度的视觉条。图形过挤时可弱化装饰，确保按钮和文字可读。依次展示主文章、近期更新、AI 趋势和个人介绍，最后放联络入口。精细对齐以手机窄屏与长名字实测为准。

### 3.2 区块与数据

1. **个人首屏**：显示名（`h1`）、定位、简短介绍和「浏览文章」「关于我」两个入口，右侧视觉区仅在资料已配置时叠放头像与所在地角标。未配置个人档案时改用站点名与站点简介，无空名片。
2. **文章精选与最近更新**：左 8 栏放 1 篇已上线精选文章（多篇时取最新），右 4 栏放最多 2 篇不重复的最新文章。没有精选时以最新文章作为主文章并移除「精选」标记；只有一篇时单卡展示。手机先主卡后短列表，标题均链接详情。
3. **AI Trending 摘要**：展示收录范围内近 7 天 Stars 净增长自然榜的前 3 项、榜单数据日期和「查看完整榜单」。复用上线快照与榜单口径，不在首页另算排名；没有成功批次显示「暂无榜单数据」。
4. **关于与联络**提供简短介绍和 `/about` 入口。仅展示已配置的公开社交链接。

## 4. 关于 `/about`

关于页沿用「身份名片 → 个人简介 → 工作经历 → 技术能力 → 联络」结构。内容从已上线 Profile 读取，不引入实时 GitHub 仓库数、语言占比或技能百分比；个人自叙可写在现有的 Markdown 简介里。[设计参考](https://clin.pro/about) · [关于页原型](../prototype-design/site/about.html)

```text
顶部导航
┌─ 档案首屏 ──────────────────────────┐
│ 关于我 / 一句话定位       个人名片   │
│ 简介引导                 头像 / 姓名 │
│                          地点 / 社交 │
├─ 个人简介 ── 背景与关注方向 ─────────┤
├─ 经历时间线 ── 日期｜职位、组织、说明 ┤
├─ 技能 ── 按分类组织的技能列表 ────────┤
└─ 保持联系 ── 公开联络 / 阅读文章 ─────┘
页脚
```

| 区块     | 布局与内容                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 档案首屏 | 左 7 栏放「关于我」与个人定位，右 5 栏放身份卡（头像、姓名、地点、已配置的社交链接）。手机先标题再身份卡；缺头像可用姓名首字或省略，不使用默认人物照片。 |
| 个人简介 | 限宽阅读区，渲染 Profile Markdown。背景、关注方向、自叙共用该正文，不强制结构化录入。                                                                    |
| 经历     | 按后台配置顺序展示。桌面日期在左、职位/组织与说明在右；手机把日期放到每段条目顶部。未知日期省略，不把缺少结束时间一律解释为「至今」。                    |
| 技能     | 按分类分组，组内依展示顺序排列；未分类时归为「其他」。熟练程度如有配置则显示原文，不换算百分比。                                                         |
| 联络     | 复用公开社交链接，提供「阅读文章」。简介、经历、技能为空时省略对应区块；未配置个人档案时保留页标题、简短说明与站内入口。                   |

## 5. 管理后台页面清单

后台列表统一为「页标题与主操作 → 筛选区（如适用） → 表格/卡片 → 分页（如适用）」。详情和表单为「面包屑 → 标题与状态 → 主内容 → 保存或下一步操作」。新建/编辑小表单用抽屉；长表单、需要独立访问的任务详情使用独立页。以下 `{id}` 和 `{revisionId}` 表示后台动态路由段，不是公开 slug。

| 路由或入口                                                    | 页面             | 布局与主要操作                                                                                                                                                |
| ------------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/login`                                                      | 登录             | 居中登录卡：站点标识、账户凭证、提交、错误提示；无公开注册入口。                                                                                              |
| `/`                                                           | 工作台           | 顶部常用操作（如新建文章） → 当前角色有权访问的文章或发布状态摘要；不把全站统计展示给 Author。                                           |
| `/posts`                                                      | 文章列表         | 按权限显示我的文章/全部文章；列表显示草稿、已上线或已上线且有新草稿，提供新建及进入编辑页的入口。 |
| `/posts/new`、`/posts/{id}/edit`                              | 文章编辑器       | 顶栏操作与保存、发布状态 → Markdown 源码与预览 → 分类、标签、封面、首页精选及 SEO 设置。在编辑页保存和发布文章；详见 §6。                         |
| `/taxonomy`                                                   | 分类与标签       | 分类/标签两个标签页，各为列表＋新增/编辑抽屉；删除前确认，存在引用时显示不能删除的原因。                                                                      |
| `/media`                                                      | 媒体库           | 上传按钮与状态 → 媒体网格 → 详情抽屉。编辑器从媒体选择器插入已就绪媒体；Author 只访问自己的媒体。                                                             |
| `/profile`                                                    | 个人资料         | 单例表单：身份与头像、Markdown 简介、可排序的经历/技能/社交链接；统一保存，独立显示上线状态。                                                                 |
| `/ai-trending`、`/ai-trending/repositories/{id}`              | AI 榜单管理      | 仓库列表显示分类、精选与隐藏状态；详情显示上游指标、快照历史与曲线，人工操作仅限隐藏/恢复、精选和分类修正，不直接编辑采集指标。                               |
| `/ai-trending/runs`                                           | AI 采集批次      | 顶部显示最近一次成功时间；列表显示 UTC 批次、状态、限流和错误，详情用行展开或抽屉；Admin 可请求当日未成功批次，运行中或已成功时显示已有记录。                 |
| `/users`、`/roles`                                            | 账户与角色       | 账户表格＋创建/编辑抽屉，支持停用、启用、删除和分配内置角色；角色页为只读列表，不编辑权限定义。                                                                     |
| `/audit-logs`、`/system/health`                               | 审计与系统健康   | 审计用事件表格和详情抽屉；健康页显示检查项与最近结果，不提供未经一期定义的运维操作。                                                                          |
| 403、未匹配路径                                               | 后台异常页       | 显示「无权访问」或「页面不存在」，提供回工作台入口；会话失效转登录，不用 404 掩盖普通的会话失效。                                                             |

账户、角色、审计、系统健康仅对 Admin 开放。Editor/Admin 可维护分类标签和个人资料，调整 AI 榜单，发布文章。Author 仅访问自身文章和媒体。导航与按钮按权限展示，直接访问 URL 仍按服务端授权处理。

## 6. 编辑、发布与状态反馈

- **编辑布局**：宽屏并列「源码｜预览」，文章设置用可收起的右栏；窄屏在「编辑 / 预览 / 设置」间切换，切换不清空表单。页头显示保存状态和发布状态，已有公开版本时提供线上文章链接。
- **保存与冲突**：明确显示「保存中」「已保存」「保存失败」「有新版本」。并发冲突时停止自动保存、保留当前输入，提示读取最新修订；不静默覆盖。媒体上传另有上传、校验、就绪、失败状态，仅就绪媒体可插入。
- **发布**。Author 可保存草稿，Editor/Admin 可在新建或编辑页直接发布。点击时自动创建或保存当前内容，使用该修订发起发布，留空的新文章 slug 自动生成。已有文章在发布期间继续输入的内容保留为草稿。取消发布单独确认，成功后按接口读回的状态显示“已上线”或“已下线”。公开分类标签及个人资料修改同步生效。
- **发布记录**。同步发布记为 `active`，被新版本替换后为 `retired`。历史记录继续显示当时的状态、时间、错误。
- **公开筛选与分页**：AI Trending 只在交互区发起请求，筛选项和页码写入 URL；筛选变更回第一页，浏览器后退可恢复。首屏来自 SSR 获取的公开快照；符合筛选的记录为零时提示「没有符合条件的结果」并给出「清除筛选」。请求失败显示重试；版本冲突清除旧数据并提示刷新，不混用不同线上版本。
- **数据文案**：AI Trending 默认按近 7 天 Stars 净增长降序，支持 30 天、Forks 增长、Stars 总数与最近更新排序。保留负值，`null` 显示「数据不足」，没有成功批次才显示「暂无榜单数据」。

## 7. 布局验收

1. 分别在 1440px、768px、375px 视口检查首页、About、文章详情、AI 榜单、后台列表与编辑器：内容无整页横向溢出，导航、主操作和状态均可访问。
2. 用无头像、无封面、无精选、无个人资料、长中英文标题和长代码块走查，布局不留空框，正文不因图片或表格撑宽页面。
3. 用键盘完成移动导航、筛选与弹窗操作；焦点可见，关闭弹窗后焦点回到触发控件，状态不只靠颜色表达。
4. 分别走查榜单无批次、筛选无结果、请求失败、站点版本变化；四种反馈可区分。
5. 以 Author 和 Editor/Admin 检查「编辑 → 保存 → 发布」及取消发布的路径：一键发布点击时的修订、越权操作不可用、回读状态与公开页面一致、保存或上传失败时输入不会丢失。
