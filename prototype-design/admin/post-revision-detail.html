用不可变 revision 重写 CMS 的发布流程：草稿、审核与上线的三条线

为什么要拆开

一篇文章同时存在三种「版本」：正在编辑的、已接受发布、等待上线的，以及访客正在看到的。把它们混成一个 status 字段，迟早会出事。

不可变修订

每次保存都创建新的 revision，旧的永不覆盖。保存请求带上 expected_revision_id：

PUT /api/v1/admin/posts/{id}
{ "expected_revision_id": "0193…", "body": "…" }

收到 409 revision_conflict 时停止自动保存，保留本地草稿。

发布不是上线

  • 发布：把一个已批准的修订设为期望公开版本
  • 上线：包含它的站点 generation 激活
  • 构建失败：线上保持原样
